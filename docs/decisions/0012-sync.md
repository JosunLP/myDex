# 0012 – Optionaler Sync

Status: angenommen; Verschlüsselung ergänzt durch ADR 0014

## Kontext
Persönliche Daten sollen sich auf Wunsch zwischen Geräten abgleichen lassen, ohne dass die App
ein Konto oder Netz voraussetzt (ADR 0002, 0003) und ohne die GrapheneOS-Abnahme (keine
unnötigen Berechtigungen) zu gefährden.

## Entscheidung
- **Selbst gehosteter Server** (`tools/sync_server`): ein Dart-Prozess mit SQLite. Konten
  bekommen einen zufälligen Zugangsschlüssel (256 Bit), gespeichert nur als SHA-256-Hash.
  Kein Passwort, keine E-Mail, kein Anbieter-Konto.
- **Umfang:** Sammlung, Teams, Filtervorlagen. Nicht abgeglichen: Einstellungen (geräteabhängig)
  und der Katalog (reproduzierbar). Serveradresse und Schlüssel liegen getrennt von den
  Einstellungen und gelangen nie in eine Datensicherung.
- **Protokoll** (`packages/sync`, Version 1): ein Aufruf `POST /v1/sync` sendet die Outbox und
  holt fremde Änderungen seit dem eigenen Cursor (seitenweise, höchstens 500 je Seite).
  - Jede angenommene Änderung bekommt eine kontoweit fortlaufende Revision.
  - Optimistische Nebenläufigkeit: Eine Änderung trägt die zuletzt bekannte Revision; weicht sie
    ab, antwortet der Server mit einem Konflikt und dem aktuellen Stand, statt zu überschreiben.
  - Löschungen bleiben als Grabsteine erhalten. „Daten auf dem Server löschen“ entfernt alle
    Datensätze, Revisionen springen aber nie zurück.
- **Outbox:** Lokale Änderungen werden je Datensatz zusammengefasst, überstehen Neustarts und
  werden wenige Sekunden nach der letzten Änderung, beim Start und auf Knopfdruck gesendet.
  Ohne Netz bleibt alles lokal nutzbar.
- **Konflikte:**
  - Sammlungseinträge: der neuere Stand gewinnt (je Eintrag).
  - Teams und Filtervorlagen: Sind beide Seiten geändert, bleibt die Serverfassung unter der ID
    und die lokale als Kopie mit dem Zusatz „(Konflikt)“. Bearbeitung gewinnt gegen Löschung.
    Es geht nie eine Bearbeitung still verloren.
- **Transport:** HTTPS; unverschlüsseltes HTTP nur zu lokalen Adressen (eigener Rechner,
  Android-Emulator). TLS übernimmt ein Reverse-Proxy vor dem Server.
- **Keine Ende-zu-Ende-Verschlüsselung** in Version 1, wie im Architekturentwurf vorgesehen. Die
  App sagt das vor dem Verbinden. Eine spätere Version kann die Datensätze clientseitig
  verschlüsseln, ohne das Protokoll zu ändern (der Server behandelt `data` als undurchsichtig).
- **Android-Ausgaben:** `offline` (Standard) ohne Internet-Berechtigung und ohne Sync;
  `sync` mit Internet-Berechtigung und eigener Paket-ID (`….sync`). Alle anderen Plattformen
  bieten den Sync optional an; macOS erhält dafür die Sandbox-Berechtigung `network.client`.

## Konsequenzen
- Wer Sync will, braucht einen eigenen Server oder einen vertrauenswürdigen Betreiber.
- Android-Builds brauchen `--flavor offline` oder `--flavor sync`.
- Grabsteine wachsen mit der Zeit; bei der erwartbaren Datenmenge (Hunderte bis wenige Tausend
  Einträge) ist das unkritisch. Ein Aufräumen alter Grabsteine kann später ergänzt werden.
